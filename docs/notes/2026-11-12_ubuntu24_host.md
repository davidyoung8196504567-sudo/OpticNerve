## Next steps (David does the installs)

1. Bring `~/qnx800` to the baseline (recommended over a new 8.0.6 baseline, which would mean updating and
   re-checking Windows too): close every Software Center, then
   `qnxsoftwarecenter_clt -mirror ...` and
   `qnxsoftwarecenter_clt -importAndInstall ~/OpticNerve/sdp/qsc-patchset-linux.txt -destination ~/qnx800 ...`
   with `-myqnx.user` / `-myqnx.password` (see [../CONFIG_MANAGEMENT.md](../CONFIG_MANAGEMENT.md)). The import
   uninstalls everything and installs exactly the list. The password lands in clear text in
   `~/.qnx/swupdate/qnxsoftwarecenter-*.log`: never print or share those logs.
2. Run `python3 sdp/check_sdp.py ~/qnx800` (no `--record`): expect `MATCHES THE BASELINE`. Since the check keys hosts
   by platform, UBUNTU24 is then checked against the same `[linux]` entries that were recorded on WSL; no new baseline is needed. If it
   differs, list the differences before recording anything.
3. Ubuntu packages, from the QNX QEMU guide plus SSH and build tools:
   `sudo apt install qemu-system qemu-utils qemu-user qemu-user-binfmt qemu-block-extra libvirt-daemon-system
   libvirt-clients libguestfs-tools bridge-utils openssh-server build-essential`, then
   `sudo usermod -aG kvm,libvirt tester` and log in again. Start with Ubuntu's QEMU (8.2); build QEMU 10 from source
   only if the QNX image fails on it.
4. Record in [../CONFIG_MANAGEMENT.md](../CONFIG_MANAGEMENT.md): UBUNTU24 as a third build host (Linux, QEMU host),
   its check result, the QEMU and libvirt versions; then boot the target with `mkqnximage --run`.
